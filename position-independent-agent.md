# The Position-Independent Agent

> **Series:** [position-independent code](position-independent-code.md) ← **PIA** · **Back to:** [intro](intro.md)

[**nostdlib/Position-Independent-Agent**](https://github.com/nostdlib/Position-Independent-Agent) compiles an entire C++23 encrypted-agent application (TLS 1.3 + WebSocket command shell, file ops, screen capture) into a single position-independent shellcode blob — across **8 operating systems and 7 CPU architectures**, with **no libc, no stdlib, no dynamic linking**. It is a working embodiment of all three shellcode constraints from [shellcode](shellcode.md), and a direct solution to every problem in [Position-Independent Code](position-independent-code.md).

- **PIC, automated.** Rather than hand-writing assembly, a custom **LLVM pass (`pic-transform`)** makes ordinary C++23 position-independent at compile time. It strips the `.data`/`.rodata`/`.bss` sections (so there are no fixed-address data references), rewrites string literals into packed immediate `mov` stores on the stack, bitcasts float constants to integers, and turns function pointers into **PC-relative** code. Output is a `.text`-only blob — the "`objcopy -O binary` flat bytes" idea from [shellcode](shellcode.md), taken to its limit.
- **Self-contained.** Every syscall (Windows NT Native API with **PEB-walking** module resolution and indirect syscalls; Linux/BSD inline-asm syscalls across 7 architectures) and every crypto/protocol primitive (SHA-2, ChaCha20-Poly1305, ECC P-256, TLS 1.3) is built from scratch — exactly the "reach the kernel directly, don't assume libc is set up" constraint.
- **The full pipeline in one project.** C++23 source → LLVM compile + PIC transform → link → flat shellcode. It is the compile → assemble → link chain from [machine code](machine-code.md), except the final step deliberately emits injectable bytes instead of an OS-loadable file.

That is "describes nothing, runs where it lands" made real. It also shows the **static-vs-dynamic** choice from [machine code](machine-code.md) collapsing: with no libc to bind against, there is nothing left for a dynamic linker (`ld.so`, the PE loader) to resolve. And the project's Python/PowerShell **shellcode loaders** — the stubs that map the blob executable and jump to it — are the "stage-0 binds the payload" staged-payload pattern from [shellcode](shellcode.md) in concrete form.
